# LeakSanitizer suppressions for third-party libraries we do not control.
#
# WHY THIS EXISTS
# Tests that create windows or initialise Vulkan (Platform, and from the graphics milestone onward the
# renderer) report ~2.1 KB "leaked in 3 allocations" at exit on this machine. The stacks are entirely inside
# system libraries: glfwInitVulkan -> libvulkan -> the vendor driver, which opens a session D-Bus connection and
# keeps its message-loader buffers registered for the process lifetime. There is no teardown entry point a client
# can call, and the allocation is correct behaviour for a library that expects to live as long as the process.
#
# Letting this fail the sanitiser gate would be worse than suppressing it: once a suite "always leaks something",
# people stop reading leak reports and real engine leaks stop being caught. So the noise is removed precisely,
# and only where it occurs.
#
# WHY THESE PATTERNS ARE SAFE
# LSan matches `leak:` patterns against frames of the allocation stack. Every entry below names a system library
# that Hollowpoint code never allocates *through* except as a side effect of calling into it, so an engine leak
# (a forgotten delete, a leaked Window, an unreleased NVRHI object) still reports. Suppressions are additionally
# applied only to the test targets that pass LEAK_SUPPRESSIONS to hp_add_module_test — every other suite runs with
# full, unsuppressed leak detection.
#
# Keep this list minimal and justified; each entry must name a library we cannot fix. Remove entries as soon as an
# upstream release stops retaining state.

# D-Bus client library: session-bus registration and message-loader state persist for the process lifetime
# (reached from the Vulkan loader / driver during glfwInitVulkan).
leak:libdbus-1

# GLib/GObject internals: type registration and default-main-context structures are intentionally permanent.
leak:libglib-2.0
leak:libgobject-2.0

# GTK 3 / GDK, loaded by libdecor when drawing Wayland server-side decorations.
leak:libgtk-3
leak:libgdk-3

# libdecor: Wayland decoration plugin handles are retained after glfwTerminate.
leak:libdecor

# GPU driver and loader state held past teardown (hardware and llvmpipe both keep contexts alive).
leak:libnvidia
leak:nvidia_dri
leak:swrast_dri
leak:libdrm
